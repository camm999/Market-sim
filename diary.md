Speed up the matching engine: `_best_bid()`/`_best_ask()` used to do `max()`/`min()` over every price level's dict key every single call — `O(n)`, and they get called on nearly every operation. Replaced with a heap-based index (`_bid_heap`/`_ask_heap`) alongside each dict: bids store negated prices to simulate a max-heap since `heapq` is min-heap only. Heaps can't cheaply delete from the middle, so used lazy deletion (the pattern `heapq`'s own docs recommend) — stale entries (price level fully matched/cancelled away) get left in place and discarded the next time they'd be the answer, each one only ever popped once, keeping it `O(log n)` amortized. Pushed onto the heap only at the two spots a genuinely new price level gets created (the resting-remainder branches in `_match_buy`/`_match_sell`); deletions need no heap changes at all, that's the whole point of the lazy approach.

Added 3 new tests specifically targeting the lazy-deletion mechanism (out-of-order inserts/removals, levels matched away, a price level emptied then reused later — the case where the heap can end up with a stale + live entry for the same price simultaneously). 33 tests total, all passing, mypy clean.

Added `benchmarks/bench_best_price.py` to actually measure the claim instead of just asserting it: dict `max()` scales linearly with price levels (2.86s at 50k levels), heap peek stays flat (~0.2-0.4ms) regardless of depth — a ~10,000x difference at 50k levels. Started Phase 1 of a market-making extension. Turned out most of it was already there from the original build — inventory skew already existed — so the actual gap was the other adaptive half: widening the spread with recent volatility.

- Added `MarketMaker._realized_volatility()` — population stdev (`statistics.pstdev`, no numpy needed here) of the last `vol_window` trade prices read straight from `book.trades`, 0 with fewer than 2 trades so a fresh/quiet book behaves exactly like before. New constructor params `vol_window` (default 20) and `vol_coef` (default 1.0, spread added per unit of volatility; `vol_coef=0` recovers the old fixed-spread behavior exactly).
- `quote()` now computes `effective_spread = self.spread + vol_coef * volatility` and splits that into the half-spread instead of the raw base `spread`. Left the existing inventory-skew formula untouched (`skew = (inventory / max_inventory) * half`) — since `half` now moves with volatility, skew automatically scales up in choppy markets too. That's the same interaction the README's tuning section already flagged as a "danger zone" (wide spread -> big skew swings against a pinned inventory cap), so it's worth another pass through `analysis/tune_market_maker.py` at some point to see whether volatility widening makes that zone worse or whether it's actually the more correct behavior (spread should widen precisely when risk is up).
- Added 4 tests to `tests/test_market_maker.py`: spread widens with a synthetic high-stdev trade history, stays at base with 0-1 trades, only looks inside `vol_window` (an old wild trade outside the window is ignored), and `vol_coef=0` disables it entirely. 48 tests total, all passing, mypy clean across the same 8 source files.

Moved on to Phase 3: stress-test the market maker against *real* adverse selection instead of just what happens to show up in random flow, and check whether the two protective mechanisms built so far (volatility widening, inventory skew) actually help.

- Added `simulator/informed_trader.py` (`InformedTrader`) — fed a ground-truth schedule of `(start_step, end_step, side)` drift windows at construction, it trades a market order in that direction every step a window is active. Its own flow *is* the drift (self-fulfilling, same way real informed order flow moves prices) — simplest possible way to inject genuine, on-purpose adverse selection rather than relying on the random walk to happen to produce some. Tracks an internal `_step` counter instead of taking a step argument, so `act(book)` matches `ImbalanceTrader`'s signature and plugs into `simulate_random_flow` the same way. Deliberately uncapped (`max_inventory=None`) by default, unlike every other agent — risk-capping is a liquidity-provider concept, and an informed trader riding a confirmed signal is expected to run its full size for the full window rather than stopping partway through (a capped default at the usual 50 would've meant the demo window goes quiet 10 steps in at size=4, undercutting the whole point).
- Added `skew_coef: float = 1.0` to `MarketMaker` (defaults to exactly the old behavior), multiplying the inventory-skew term — `skew_coef=0` disables quote skewing entirely, needed as the other half of an A/B test alongside the existing `vol_coef`.
- Added `inventory: List[int]` to `PnLHistory`, recorded alongside the P&L series each step — needed to measure how fast a position mean-reverts after a shock (position size, not P&L, is what "mean-revert" in Phase 3's brief actually means).
- Wired `InformedTrader` into `simulate_random_flow` as a new optional param, called right after `imbalance_trader.act()` — by that point the MarketMaker has already reposted its quote for the step, so the informed trader picks off the *current* quote rather than a stale one.
- Added `analysis/stress_test_market_maker.py`: a single seeded demo scenario (two 50-step windows, buy then sell, spaced out so inventory can fully mean-revert between them) plotted as P&L-over-time with the windows shaded, plus a `vol_coef x skew_coef` grid (`{0,1} x {0,1}`, 30 seeds) measuring per-window `inventory_pnl` drawdown and post-window mean `|inventory|`.
- Real run, `python -m analysis.stress_test_market_maker`: the demo plot is exactly the "watch it happen live" picture Phase 3 asked for — `spread_pnl` climbs steadily through both shaded windows (still earning its edge on every fill, as the "spread P&L can't go negative" property from Phase 2 guarantees) while `inventory_pnl` craters right as each window opens (finished at +1608 vs -2409, net total -800). Genuinely surprising result from the grid: skew helps mean-reversion cleanly and consistently regardless of `vol_coef` (lower `mean_|inventory|_after` at `skew_coef=1` in both rows: 38.29 vs 45.99 at vol_coef=0, 32.89 vs 45.67 at vol_coef=1) — but widening does *not* uniformly help drawdown. At `skew_coef=0` it helps as expected (-272.89 -> -201.00), but at `skew_coef=1` it makes drawdown almost 3x *worse* (-444.77 -> -627.10). Root cause: `skew = skew_coef * (inventory/max_inventory) * half`, and `half` grows with `vol_coef` — so widening multiplies directly into a bigger absolute skew once an informed trader has already built up inventory, amplifying exactly the exposure it's supposed to guard against. This is a live reproduction of the "danger zone" `tune_market_maker.py` could only hypothesize about from a P&L heatmap back on 08-23 - same underlying mechanism (skew scaling with spread), now isolated and confirmed as the actual cause rather than just a correlated pattern in a grid.
- Flagged (in the README, not hidden) one confound in the drawdown numbers: the informed trader always fires *market* orders, which are marketable regardless of spread — widening doesn't block its trades, it changes who absorbs them (a wider MM quote sits further from the top of book, so more flow goes to other resting random-flow orders instead). Both effects are real and both are baked into the numbers; they're just not separable from this experiment alone.
